# Pipeline Comparison Report
## PSS → PLP → Capsule → DCK

**Date**: 2026-07-29  
**DCK Version**: v0.9  
**Script**: `examples/pipeline_comparison.py`  
**Input**: 日常会話（姫路の天気に関する5ターン対話）

---

## 1. 実験の目的

単体性能ではなく、**役割分担が成立するか**を見る。

特に確認したいこと：

- Capsule が「維持すべき状態」として働くと、DCK が扱う差異（gap）がどう変化するか
- PLP の平滑化が一時的な大きな逸脱（Turn 3）をどう緩和するか
- PSS 単体ではどの程度の効果があるか
- 結果として「探索量（gap の大きさ・消費リソース）」が減っているか

---

## 2. 条件定義

| 条件 | パイプライン | 説明 |
|------|--------------|------|
| **A** | DCK only | 生テレメトリを直接 DCK に流す（ベースライン） |
| **B** | PSS → DCK | PSS が問題を構造化してから DCK へ |
| **C** | PLP + Capsule → DCK | 履歴平滑化 + 「維持すべき状態」による拘束 |
| **D** | PSS → PLP → Capsule → DCK | フルパイプライン |

### 各コンポーネントの役割（今回の最小実装）

- **PSS**: 生の状態を「解くべき問題」として受け渡す
- **PLP**: 直近履歴で平滑化し、急激なノイズ（特に Turn 3 の大きな落ち込み）を減衰
- **Capsule**: 観測値を desired 状態方向へ引き寄せる（pull=0.60）。探索空間を削る「制約」として機能
- **DCK**: 差異の検出・意思決定・リソース付き実行

### 読み取りポイント

| 指標 | A / B（Capsuleなし） | C / D（Capsuleあり） | 変化 |
|------|----------------------|----------------------|------|
| 平均 Gap | 0.276 | **0.137** | **約50%削減** |
| Turn 3 Gap（最大逸脱時） | 1.568 | **0.352** | **約78%削減** |
| 最終 Capital | 997.24 | **998.63** | 消費が約半分 |
| EXEC 回数 | 10 | 10 | 同じ（閾値設定による） |

---

## 4. 解釈

### 4.1 Capsule の効果は明確

Capsule を入れるだけで：

- DCK が観測する差異が大きく縮小した
- 特に「一時的に話題が広がった Turn 3」での gap が激減した
- リソース消費も比例して減った

これは「記憶」ではなく **「この状態を維持する必要がある」という制約** として Capsule が機能していることを示している。

LLM の自由探索を減らす方向の効果が、数値として現れている。

### 4.2 PSS 単体の効果は今回ほぼ見えなかった

A と B がほぼ同一なのは、今回の PSS 実装が「構造化して渡す」だけに留めており、値そのものを大きく変えていないため。  
PSS が本領を発揮するのは、より複雑な問題仕様（依存関係・優先度・複数制約）を生成する段階だと考えられる。

### 4.3 PLP の平滑化は Capsule と組み合わさって効いている

Turn 3 の大きな落ち込みを PLP が先に減衰させ、その上で Capsule が desired 方向へ引っ張ることで、DCK に届く信号がかなり穏やかになっている。

---

## 5. この結果が示唆すること

ご指摘の通り、

> 「LLMの自由探索が減っているのに、結果品質が落ちないか」

を測る実験として、今回の結果は良い方向の兆候を示している。

- Capsule が探索空間を削る
- DCK がその削られた空間上で差異収束を担当する
- 結果として「無駄な大きな修正アクション」が減る（gap とリソース消費の減少）

という役割分担の形が、少なくともこの最小実装では観察できた。

次の自然な拡張は：

1. Capsule の pull 強度を変化させて、探索削減量と最終品質のトレードオフを測る
2. PSS に「より厳密な問題仕様（複数 Intent・依存関係）」を生成させる
3. 実際の LLM を Observer / Predictor / Executor に差し替えて、トークン数・自己修正回数を比較する

## 7. まとめ（現時点）

| レイヤ | 観察された役割 |
|--------|----------------|
| PSS | 問題の入り口（今回は効果薄） |
| PLP | 急変の平滑化 |
| Capsule | **探索空間の削減（最も効果が明確）** |
| DCK | 差異の検出と収束実行 |

DCK の立ち位置は「AIを賢くする装置」ではなく、  
**「AIの知能を効率的に使うための制御系」** として説明できる可能性が、この比較実験からも支持されている。
